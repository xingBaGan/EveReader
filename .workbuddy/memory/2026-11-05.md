# 2026-11-05

## adb 调试环境（本机 / 测试机）
- 测试机：Xiaomi/Redmi `24122RKC7C`（代号 miro），1080x2400 @450dpi，HyperOS，通过 Wi-Fi 无线调试连接。
- `adb devices` 会同时出现两条记录（手动 `adb connect IP:port` + mDNS `_adb-tls-connect` 自动发现），同一台物理设备。所有命令必须带 `-s <serial>`，否则报 `more than one device`。
- 该机 `adb shell input tap/keyevent` 被系统拒绝：`java.lang.SecurityException: Injecting input events requires ... INJECT_EVENTS permission`（HyperOS/MIUI 的模拟输入限制）。需在开发者选项打开「USB 调试（安全设置）」（要求登录小米账号 + 插 SIM 卡）；`screencap` 和 `uiautomator dump` 不受影响，可正常读屏。
- 无线调试会在锁屏/息屏/长时间无连接后自动关闭，端口是随机的，重开后 IP:端口会变，需要重新配对或重新 connect。
- 排查备用方案：`monkey -f` 脚本注入事件（部分 HyperOS 版本能绕过 `input` 的注入拦截）。

### 已验证：开关打开后可用（22:02 复测）
- 打开「USB 调试（安全设置）」并重连后，`adb -s 192.168.0.105:41219 shell input keyevent 0` 无报错（可作无副作用权限探测）。
- Wi-Fi 连接下模拟点击成功：在 `com.anonymous.zlibapp`（本项目 App）点底部「搜索」(405,2307) → 页面切到搜索页，点「我的」(945,2307) → 回到个人中心，截图确认。结论：Wi-Fi adb 的 `input tap` 与 USB 等价，之前的失败纯粹是 HyperOS 安全开关。
