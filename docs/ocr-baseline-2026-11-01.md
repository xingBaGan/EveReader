## 1. 怎么在没有点击权限的情况下驱动检测

MIUI 禁用了 `adb shell input`（`INJECT_EVENTS` 缺失），但 App 是 debuggable 的，WebView 调试通道可用：

```bash
adb -s 192.168.0.105:36891 forward tcp:9333 localabstract:webview_devtools_remote_$(adb -s 192.168.0.105:36891 shell pidof com.anonymous.zlibapp)
node .dsh/cdp.mjs 'window.receiveMessageFromNative(JSON.stringify({action:"toggleBubbleDetection",active:true,requestId:1}))'
```

检测结果由 RN 回灌到 WebView 的 `setDetectedBubbles`，可包装 `window.receiveMessageFromNative` 截获原始气泡数组（含 box/文本/置信度），同时 `canvas.toDataURL()` 可取到**与原生输入完全一致的图像**。整条链路 0 次触摸。

一键跑分：

```bash
node .dsh/ocr-eval/run-eval.mjs 6,7,8      # 逐页翻页+检测+落盘 .dsh/ocr-eval/pages/pN.{jpg,json}
```

## 4. 问题分类（按性价比排序）

**P0 延迟**：6 s/页无法接受。当前逐块跑 4 条通道、且 Manga-OCR 多数时候被判负（`[OCR_WINNER]` 多为 mlkit）。需要：分阶段打点 + 通道裁剪 + 并发/批处理 + 页级缓存。

**P0 幻觉与文本准确率**：
1. Manga-OCR 在 224×224 拉伸下大面积幻觉（`ああああははっははははあはは`），需按竖排/横排旋转+padding 预处理，或直接对低置信度样本禁用。
2. 艺术字/标题区被当作普通文本识别，输出与画面无关（`あそれ`），应在置信度联合判定后**宁可留空也不要幻觉**（可评估的精确率优先）。
3. 竖排多列阅读顺序错乱（`勧げ前誘`），需要按列切分而非按 bbox 宽高比猜方向。
4. 人名/常用词缺纠错表（足立/宗太/宮子）。
5. 注音（furigana）未剥离、混入正文（`きゅうさい`）。

**P1 检测与分类**：
1. 同一艺术字区域被两个框重复命中（#2/#8）。
2. 拟声词漏检（ピンポーン♪）。
3. `textType` 分类不可靠（对白被判 sfx），会影响后续字号/排版决策。

## 5. 建议验收口径（可自动化）

- 延迟：同 3 页均值 ≤ 2000 ms，P95 ≤ 3500 ms（warm）。
- 文本：第 6/7/8 页气泡类 CER ≤ 8%，艺术字类**幻觉率为 0**（允许空串）。
- 检测：人工 GT 框 IoU≥0.5 召回 ≥ 90%，重复框（IoU>0.6 且文本相同）为 0。
- 回归：`tests/bubble-rules.test.js` + 新增 3 页 fixture 全部通过。
